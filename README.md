# 산업 리포트 Q&A 챗봇

산업보고서 PDF를 하나의 지식베이스로 묶어, 질문 한 줄로 **출처 보고서명 + 페이지 번호**와 함께
답을 돌려주는 범용 RAG 챗봇입니다.

특정 산업 전용이 아닙니다. 다루는 산업은 코드가 아니라 **지식베이스 정의(`data/sources.json`)** 가
결정하므로, 보고서만 교체하면 반도체·2차전지·조선 등 어느 산업에서도 그대로 동작합니다.
현재 배포본에는 시연용으로 **데이터센터 산업 보고서 6종**이 미리 색인되어 있습니다.

---

## 1. 기획 의도 — 어떤 실무 문제를 푸는가

산업 리서치에서 수치 하나를 확인하려면 증권사·연구기관·국제기구 보고서 수백 페이지를 매번 열어
Ctrl+F로 뒤져야 합니다. 보고서마다 수치와 기준연도가 달라 어느 자료의 숫자인지 다시 대조해야 하고,
그 대조 과정이 리서치 시간의 상당 부분을 잡아먹습니다.

이 앱은 그 과정을 대체합니다.

- 흩어진 보고서를 한 번에 검색
- 답변의 **모든 문장에 근거 번호**를 달고, 실제 발췌문과 페이지를 함께 표시
- 보고서마다 수치가 다르면 **차이를 그대로 드러내도록** 프롬프트에서 강제
- 자료에 없는 내용은 "제공된 보고서에서는 확인되지 않습니다"로 응답 (환각 억제)

## 2. 두 가지 사용법

| 방식 | 설명 |
|---|---|
| **기본 지식베이스로 바로 질문** | 미리 색인된 보고서에 대해 접속 즉시 질문 가능 (설치·업로드 불필요) |
| **내 보고서 업로드** | 사이드바에서 PDF를 올리면 세션 한정 인덱스로 즉시 색인되어 함께 검색됨 |

기본 지식베이스와 업로드 문서는 **같이 검색**되므로, 공개 보고서와 사내 자료의 수치를
한 화면에서 대조할 수 있습니다.

## 4. 다른 산업으로 교체하는 방법

앱 코드는 손대지 않습니다.

1. `data/pdfs/` 의 PDF를 원하는 산업 보고서로 교체합니다.
2. `data/sources.json` 의 `collection`(산업명·요약·예시 질문)과 `documents`(문서 메타데이터)를 채웁니다.
3. `python scripts/build_index.py` 로 인덱스를 다시 만듭니다.

`collection.industry` 값은 답변 프롬프트의 담당 영역("당신은 ○○ 산업을 담당하는 애널리스트입니다")에
그대로 반영되고, 화면의 예시 질문도 `collection.sample_questions` 와 각 문서의 `topics` 에서 자동 생성됩니다.
예시 질문을 따로 지정하지 않으면 산업 무관 일반 질문으로 채워집니다.

## 5. 주요 기능

| 기능 | 설명 |
|---|---|
| 근거 인용 답변 | 답변 문장마다 `[1]`, `[2]` 근거 번호 + 발췌 원문/페이지/원문 링크 표시 |
| 하이브리드 검색 | 임베딩 의미 검색 + BM25 키워드 검색을 RRF로 결합 (고유명사·수치·약어에 강함) |
| 문서 필터 | 사이드바에서 특정 보고서만 골라 검색 범위 한정 |
| 내 PDF 추가 | 업로드한 보고서를 세션 한정 인덱스로 즉시 병합 검색 |
| 멀티턴 대화 | 직전 대화를 참조해 "그럼 국내는?" 같은 후속 질문 처리 |
| 스트리밍 응답 | 토큰 단위로 답변 출력, 응답 시간·사용 모델 표시 |
| 배포 가드레일 | 세션당 질문 수·업로드 용량·질문 길이 제한으로 공개 배포 시 비용 폭주 방지 |

## 6. 핵심 기술 스택

| 영역 | 사용 기술 |
|---|---|
| UI / 배포 | Streamlit (`st.chat_message`, `st.write_stream`, `cache_resource`), Streamlit Community Cloud |
| LLM | OpenAI `gpt-4o-mini` (사이드바에서 `gpt-4.1-mini` / `gpt-4o` 전환 가능), 스트리밍 |
| 임베딩 | OpenAI `text-embedding-3-small` (1536차원, L2 정규화) |
| 벡터 검색 | NumPy 내적 기반 코사인 유사도 — 네이티브 의존성(FAISS 등) 없이 배포 안정성 확보 |
| 키워드 검색 | `rank_bm25` + 한국어 어절/음절 bigram 토크나이저 (형태소 분석기 없이 동작) |
| 랭킹 결합 | Reciprocal Rank Fusion (k=60) |
| 문서 처리 | `pypdf` 페이지 단위 추출 → 문장 경계 인지 청킹(900자/150자 오버랩) |
| 보안 | API 키는 Streamlit Secrets / 환경변수에서만 로딩, 저장소에 키 미포함 |

### 설계상의 선택

- **도메인을 코드에서 분리**했습니다. 프롬프트의 담당 영역, 예시 질문, 화면 문구가 모두
  `sources.json` 에서 나오므로 산업 교체 시 코드 수정이 없습니다.
- **인덱스는 사전 빌드 후 커밋**합니다. 배포 환경에서 재임베딩하지 않으므로 첫 응답이 빠르고
  콜드 스타트마다 임베딩 비용이 발생하지 않습니다.
- **FAISS/ChromaDB를 쓰지 않았습니다.** 청크 수천 개 규모에서는 NumPy 내적으로 충분히 빠르고,
  네이티브 빌드 의존성이 없어 Streamlit Cloud 배포 실패 위험을 없앨 수 있습니다.
- **konlpy/mecab을 쓰지 않았습니다.** JVM·네이티브 설치가 필요해 배포가 깨지기 쉬워,
  음절 bigram 근사로 대체했습니다.
- 임베딩 행렬은 **float16**으로 저장해 저장소 용량을 절반으로 줄였습니다(검색 품질 영향 미미).

## 7. 프로젝트 구조

```
.
├── app.py                     # Streamlit 앱 (UI + 대화 루프)
├── rag/
│   ├── config.py              # 설정값, API 키 로딩 우선순위
│   ├── catalog.py             # 지식베이스 정의(산업 메타데이터 + 문서 목록)
│   ├── pdf.py                 # PDF → 페이지 → 청크
│   ├── embeddings.py          # 임베딩 배치 호출 + 재시도
│   ├── index.py               # 하이브리드 인덱스 (코사인 + BM25 + RRF)
│   └── answer.py              # 프롬프트 구성 + 스트리밍 답변
├── scripts/
│   ├── download_reports.py    # sources.json 의 URL로 원문 PDF 내려받기
│   ├── build_index.py         # 인덱스 생성 (배포 전 1회)
│   └── smoke_test.py          # Streamlit 없이 파이프라인 점검
└── data/
    ├── sources.json           # 지식베이스 정의 ← 산업 교체 시 여기만 수정
    ├── pdfs/                  # 원본 PDF
    └── index/                 # 커밋되는 검색 인덱스
```

## 8. 로컬 실행

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
echo OPENAI_API_KEY=sk-... > .env
python scripts/build_index.py     # 인덱스가 없을 때만
streamlit run app.py
```

## 9. Streamlit Community Cloud 배포

1. 이 폴더를 GitHub 저장소로 push 합니다. `data/index/`는 **반드시 함께 커밋**하고,
   `.env` / `.streamlit/secrets.toml`은 `.gitignore`로 제외합니다.
2. [share.streamlit.io](https://share.streamlit.io) → **New app** → 저장소/브랜치 선택,
   Main file path는 `app.py`.
3. **Advanced settings → Secrets**에 아래를 붙여넣습니다.

   ```toml
   OPENAI_API_KEY = "sk-..."
   ```

4. Deploy 후 **시크릿 창(또는 다른 기기)** 으로 접속해 예시 질문 1건을 실행,
   답변과 근거가 정상 출력되는지 확인합니다.

키가 Secrets에 있으면 방문자는 별도 입력 없이 바로 사용할 수 있고,
키가 없는 환경에서는 사이드바에 키 입력란이 자동으로 나타나 앱이 죽지 않습니다.

## 10. 한계

- 스캔 이미지 PDF는 텍스트 추출이 되지 않습니다(OCR 미적용).
- 표·차트 안의 숫자는 추출 과정에서 구조가 깨질 수 있어, 중요한 수치는 근거 발췌와 원문 확인을 권장합니다.
- 업로드 문서는 세션이 끝나면 사라집니다(서버에 저장하지 않음).
- 답변은 수록 보고서 기준 시점의 정보이며, 투자 판단의 근거가 아닙니다.
